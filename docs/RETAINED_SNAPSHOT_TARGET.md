# 存活准备会话的目标与原生决定保活

## 当前范围

- `FrozenSource::verify_prepared` 成功后，不再释放目标组合包、内层 Data、对象目录、两份清单、浏览器原始草稿及可选 LAN 状态副本的实际句柄。所有对象文件使用零共享读取，目录和全部祖先拒绝删除共享。
- 同时持有实际原生 catalog、独占锁、目录绑定文件、准备记录目录、原始意图和成功决定。护栏只能从当前 `Catalog` 验证过的成功决定、实际目标物理身份及当前来源／LAN 检查点构造；可克隆的清单与回执仍仅是元数据，不是护栏或权限。
- 这是存活准备会话内的完整源／目标保活，不是正式切换事务。默认入口、版本和分支不变，不提交、推送或发布；历史 profile 归属、生产接管、真实所有权移交、持久切换／恢复／完整回退与可信 helper 分发仍未完成。

## 核验与生命周期

- 后续增量已增加从这些保留对象句柄准备实际运行 Data，并继续保留源／快照／原生决定；输出自身有独立意图／清单／决定和存活护栏。仍未执行真实启动或生产切换，详见 [运行 Data 准备](RUNTIME_DATA_PREPARATION.md)。本文件以下验收数字仅属于目标保活阶段。

- 首次查询在同一组原始句柄上完成静态清单验证、逐对象完整 SHA-256、原生成功决定验证和完整活源资产枚举。目标根目录、Data 根目录和目标父目录必须匹配原生回执／意图的真实身份，复制包不能获得存活权限。
- 同 ID 再次查询复用原句柄，重新计算目标清单、草稿、LAN 状态、全部 Data 对象、原始意图／决定及活源资产摘要；不会先释放再重开，避免与自己的零共享句柄冲突。同会话仍拒绝另一 ID 和再次准备。
- `confirm` 复核目标根目录、Data 和 objects 的精确名称集合，以及保留文件的身份、大小、最后写入时间、只读属性和单硬链接约束。持有目录句柄不能阻止创建子条目，因此目标固定后新增文件也会令确认失败；不删除该文件或改写原准备决定。
- 新目标哈希循环逐个文件及每个 64 KiB 块检查取消和实际来源授权。现有条目、路径、清单和字节上限继续适用；真实写者阻断、校验失败或中途取消会释放构造中的部分句柄，不强制解锁或放宽共享。
- helper 正常关闭、失败退出或被强制终止后，由实际进程生命周期释放源／目标／原生决定句柄。持久成功决定保留，但旧回执不延续会话权限；重开必须重新取得当前来源和原 LAN 独占、读取真实决定并完整复核源与目标。
- 普通静态 `verify`／`verify_receipt` 保持原返回和序列化格式，在返回后释放临时护栏。静态内容校验仍可检查复制包；原生回执和存活护栏则要求原物理目录。它们均不能反序列化为一次真实生产切换许可。
