# 受管数据与隔离组合交接快照

## 当前状态

- `src-tauri/src/managed_snapshot.rs` 是 Windows 本机受管 Data 目录的存储内核。隔离主窗现通过 `data_snapshot_prepare` 原生命令与“准备隔离 Data 快照”按钮接入持久准备记录、既有全编辑器维护和启动中断恢复；仍不是生产迁移入口或完整灾难恢复工具，没有自动生产来源发现、正式路径切换或恢复写入。
- 内核捕获所提供 Data 根下的全部普通文件与目录，保留工作区原始 JSON、便签／剪贴板资产、受管收纳内容、原始日志、备份及空目录；不按扩展名筛掉未知文件，不规范化 JSON，不重写绝对引用。只排除根下原生运行锁 `workspace.lock`，并在清单记录实际排除名；同名目录不是运行锁，必须报错。
- Data 内核不包含独立原生 userData 中的 LAN 状态／身份、浏览器 profile 或外部桌面／启动器目标。新增组合协调器在同一维护中另封存白名单草稿和原始 LAN 状态，但身份仅绑定原 profile 的物理证明，外部传输文件仍需保留原位置；不把 LAN 私钥写进数据快照或日志，不能代替独立灾难备份。
- 该格式是应用受管内容快照，不是 NTFS/VSS 镜像；未复制安全描述符、备用数据流等完整文件系统元数据。含有这些额外语义的收纳文件、外部引用、身份及回滚日志，仍需在生产组合协议中补齐并验收，不能只凭本内核通过就切换。

## 调用前提与原生授权

- `prepare(source, destination, workspace_sha256, cancel, require_active)` 只能由原生协调器选择路径及传入检查点。生产调用者须先完成所有参与编辑器最终保存、后台服务与文件任务收尾、工作区队列封存，并持续持有真实 Data 目录的跨运行时独占所有权；还须阻断不识别新锁的旧版进程。内核的回调核验不能替代这些前提。
- 存储内核自己不取得运行时命名管道锁、不停止服务。隔离原生调用现从实际 `WorkspaceStore` 取得源目录，持续保留它的跨运行时独占所有权及存储队列，调用既有全编辑器保存／冻结、LAN 停机和后台任务收尾协议，并逐块复核原生维护租约与目录所有权；孤立内核测试提供 `|| Ok(())` 仍不构成产品协调证明。
- 原生调用者必须验证目标不在 Data、浏览器 profile、LAN、资产临时目录等任何受保护目录中。当前隔离命令固定保护实际 profile 根（含 Data／WebView2／LAN）及准备记录目录，用真实祖先目录身份比较，覆盖 verbatim 别名；目标父目录由真实 Windows 文件夹选择框取得并固定，新子目录名由原生生成。生产额外目录、来源认证和未识别旧进程的保护仍未接通。
- `Receipt` 由原生准备目录持久保存，绑定实际源、记录目录和目标目录身份，渲染进程不能提供路径、源检查点或回执来替代。Data 回执仅证明该次 Data 准备；新增组合回执另绑定白名单草稿与 LAN 原状态／原身份引用，但两者均不是生产切换决定，外部收纳与传输内容、生产来源和完整恢复仍须补齐。

## 原生持久准备与启动恢复

- `managed_snapshot/preparation.rs` 提供受控记录目录，`workspace/snapshot_preparation.rs` 将它接入实际所有权、隔离主窗与 `WorkspaceStore::open`。目录名由源物理 volume／file 身份原生派生，位于 Data 的 profile 父目录下，不进入自身 Data 快照，也不由渲染进程选择。
- `catalog.json` 绑定随机目录代次、实际源身份与记录目录身份；`catalog.lock` 以独占原生文件句柄持有，进程结束由操作系统释放，不依据 PID／锁文件存在猜测所有权，不删除所谓“过期锁”。绑定文件在会话内持续固定；逐字节复制记录或用另一个源目录打开会被拒绝。
- 每次原生操作建立新的 UUID 子目录。先将 `intent.json` 写入、刷新、按精确句柄不覆盖发布并读回核验，才开始创建外部快照；意图记录原生维护请求、原始工作区摘要、实际选定目标与父目录身份，并绑定目录代次摘要。
- 完整 Data 复制、原生回执核验与维护复核后，只追加一次 `decision.json`，绑定意图原始字节摘要及 Prepared 回执。既有意图／决定从不覆盖或反转；每份记录最多 128 KiB，每个源最多 4096 次记录，超限或未知内容拒绝，不静默清理历史。
- 取消、源不符、链接拒绝、写入故障或撤权会保留未决意图及不完整／已完成外部目录。启动取得实际工作区所有权后，在普通存储访问前，将没有决定的有效意图持久标为 Aborted；即使 `snapshot.json` 已存在，也不会升级为 Prepared，不会删除外部目录或回写 Data。新请求遇到未决意图必须先重启完成原生恢复。
- 记录损坏、丢失意图、硬链接、junction、只读／占用或决定路径类型冲突导致恢复失败时，阻止工作区打开，保留原文、决定与副本；不自动修改属性／ACL、不自动重试发布或递归删除。用户明确排除真实原因后再重启，重新核验并只中止未决记录。目录初始化自身中断且留下无法识别内容时也失败关闭，当前没有自动清理入口。
- 启动恢复只核验历史终态记录及其绑定，不要求旧快照介质始终在线，也不将 Prepared 当成当前生产切换许可。实际使用前必须显式 `verify_prepared`，从原生记录取得目标并复核父目录身份、目标目录身份、清单与全部对象；移动／复制／损坏的目标不能通过。历史快照丢失不应使普通编辑永久依赖该旧备份介质。
- 全编辑器维护仍使用既有两分钟 Ready 租约，逐块检查过期，不自动续租；超时停止且不截断。不承诺本轮快照支持任意容量在租约内完成。原生成功决定发布后若发生主窗失效／旧进程出现／收尾失败，界面可能报失败或警告而留下历史 Prepared；该记录依然不授权当前接管。
- 进程退出测试覆盖意图已落盘、对象／完成清单已落盘但无决定，以及成功决定已落盘三个边界；不将进程退出等同 OS 崩溃、物理断电或完整生产切换恢复证明。

## 隔离组合交接与 V2 整体决定

- `workspace/handoff_snapshot.rs::handoff_snapshot_prepare` 仅授权实际主窗；通过真实原生文件夹选择生成新目标，拒绝实际 profile 及物理祖先别名。复用全编辑器保存／冻结、后台与 LAN 收尾及 Ready 租约；实际浏览器绑定在采集前后复核，复用 `draft_export` 的逐项白名单校验与原始值归档，不接收 renderer 的源、目标、检查点或回执。
- 先在实际 Data 中保留浏览器原生谱系回执，再捕获 Data，因此包内 Data 也包含该原始回执；稍后失败可留下未使用的导出回执，它不构成组合成功或切换授权。组合前固定原 LAN 目录／祖先、原身份与状态文件，并取得与 Rust／准备 Electron 共用的真实目录租约，直到整体封存结束才释放。
- `lan/migration.rs::Frozen` 只读原 profile，不生成证书、不创建未使用的 LAN 根、不写状态或运行锁。状态存在而原身份缺失（包括空对象状态）拒绝；身份要实际解析并验证证书／私钥匹配，使用定长有界、销毁清零的输入缓冲，不把私钥字节放入清单、回执或错误。检查点只含原 profile／LAN 物理身份、原身份 ID／公钥指纹和身份／状态文件身份、大小、时间、摘要。
- 原始 `state.json` 原样保存，不调用重启规范化编码器；拒绝重复任务及瞬态文本／token／controller／running，保留 enabled、trusted 和既有未知字段。状态最多 64 MiB、身份最多 1 MiB；每块复核取消、维护、文件身份、单硬链接及摘要，源变化或原本缺失的文件出现均拒绝。`reopen_original` 只能核验原 profile 中同一原身份／状态，复制 profile 或替换身份不能冒充原来源。
- Data-only 原生意图／决定继续为 V1，原始字节格式不变。组合意图／决定为 V2，意图在任何目标创建前额外绑定草稿与 LAN 检查点的 `componentsSha256`；只有 Data 回执、全部附件、最后发布的 `handoff.json` 及物理目标回执复核后，才追加唯一 `handoffPrepared` 整体决定。类型／版本不符、组件摘要不同、未知字段或既有决定冲突均失败关闭；旧预览不能把 V2 静默当成 V1。
- 启动恢复兼容同一原生目录中的 V1／V2，只将有效未决意图中止为 Aborted；不会因 `Data/snapshot.json` 或 `handoff.json` 存在而补写成功。普通启动不要求旧介质在线；实际使用须从原生记录显式 `verify_handoff`，复核父目录、外层和内层物理身份及全部内容，历史成功不是当前维护或切换授权。

```text
<原生生成的 DustDesk-Handoff 新目录>/
  Data/objects/...          # 既有 Data 数字对象
  Data/snapshot.json
  browser-drafts.json       # 既有完整白名单归档
  lan-state.json            # 仅原来存在持久状态时生成
  handoff.json              # 整体清单，最后发布
```

- 整体清单严格绑定 Data 回执、浏览器归档／载荷摘要、条目数与原生浏览器绑定，以及原 LAN 检查点；固定 `identityMode=original-profile-only`、`externalTransferFiles=original-locations-required`。外层清单最多 128 KiB，草稿／状态各最多 64 MiB；附件分块刷新并读回，拒绝多余／缺失组件，包括意外的 `identity.json`。单纯 `bundle::verify` 只检查归档信封／头部／数量／摘要，不能替代未来消费者的完整白名单与原生谱系校验，更不授权导入。
- 此包只能服务于保留原 profile、原身份与原外部文件的隔离交接准备；不包含私钥、外部发送源、接收终文件／分片或浏览器 cookies。整体字节完整性允许副本通过，但复制的目标不能通过原生物理回执。原身份复用证明不等于可携带的密钥备份，不能宣称完整回退、生产接管或灾难恢复已交付。
- 11 项 LAN 原生测试覆盖实际互斥、写入／改名固定、无初始化、原身份要求、复制／替换拒绝、状态变化、错误不泄露私钥、瞬态内容拒绝、取消、硬链接／junction／占用及实际超限文件。6 项组合测试覆盖完整组件、未使用 LAN、副本完整性与授权分离、组件篡改与恶意重算头部、检查点／决定不符，以及四个真实子进程退出边界（整体意图、内层清单、外层清单无决定、最终决定）。进程退出仍不等于物理断电证明。
- `tests/tauri-handoff-snapshot.mjs` 七项真实原生检查覆盖取消／受保护路径、实际快速记录和组件草稿、原样白名单与 cookie 排除、原 enabled LAN 状态／身份无变更与服务恢复、错误窗口／伪造参数、无效白名单及真实硬链接失败后 V2 启动中止，以及正常退出后准备 Electron 的实际目录谱系接受。证据和截图位于 `artifacts/tauri-migration/handoff-snapshot-native/`；完整冻结报告仍须匹配当前源码，不能用早期定向通过替代。

## 固定源与复制

- 复用 `lan/files.rs` 的 Windows 原生目录链固定、重解析点与本地盘校验；每一级祖先拒绝删除共享，覆盖大小写和 verbatim 盘符别名。网络路径、映射网络盘、符号链接／junction 和特殊文件拒绝，不跟随到源外。
- 在创建目标前枚举并固定全部普通源文件。文件句柄拒绝共享读写和删除，已存在写句柄时失败；只接受单硬链接普通文件。复制期间源文件及祖先不能被重写、替换或改名，结束前再复核文件身份、大小、修改时间、只读属性和目录清单；新增文件不能静默遗漏。
- 源 `workspace.json` 必须存在、是普通文件且不超过 64 MiB，实际 SHA-256 必须等于原生封存的原始字节摘要。该检查只确认已知检查点，不代替产品的工作区 schema／引用校验。
- 文件以 64 KiB 分块复制并计算 SHA-256，每块检查取消和原生维护上下文。目标对象刷新后通过自身句柄再读回核验；最终还独立固定全部目标对象、核对清单和逐项摘要，避免只核验写入前缓冲区。
- 上限为 65,536 个文件／目录条目、累计 4 MiB 相对路径 UTF-8、每路径 32,767 UTF-16 单元和 128 层目录、1 TiB 文件总量、64 MiB 清单。超限报错，不截断；生产数据超过边界时必须阻止切换或扩展并重新验证，不能漏掉资产以便通过。
- Windows 设备名、备用流形式、父路径、反斜杠逃逸、路径冲突和无效 Unicode 名称拒绝，不采用有损替换。时间使用原始 NT 文件时间的固定十六进制字符串，另外记录只读属性；这些记录尚未接入恢复写入。

## 目录与清单

```text
<用户原生选择的新目录>/
  objects/
    000000.bin
    000001.bin
    ...
  snapshot.json
```

- 目标必须是不存在的新目录；不覆盖、合并或递归清理已有目录。对象名由原生顺序编号生成，原文件名只作为清单中的已校验相对路径，不直接用于物化输出。
- `snapshot.json` 的 format 为 `dustdesk-managed-data-snapshot`、version 为 1。头部包含随机 v4 UUID、创建时间、应用版本、原生源路径／目录身份、工作区原始摘要、运行锁排除项，以及严格有序的文件／目录条目。
- 目录条目记录路径与原生身份；文件条目记录路径、源文件身份／大小／修改时间、只读属性、对象编号及实际字节摘要。回执再绑定清单原始字节摘要、目标物理目录身份、源身份、工作区摘要、文件／目录数量和总字节。
- 所有对象成功复制、刷新和复核后，才通过精确句柄、不覆盖已有文件的原生重命名发布 `snapshot.json`。失败保留新建的不完整目录，不自动删除或选择旧快照。没有完成清单一定不算完成；有清单也不等于原生准备成功，例如发布后撤权或最终核验失败仍必须拒绝授权。
- 当前 `sync` 与验证并不等于物理断电／OS 崩溃持久性证明。生产协议还需持久意图、决定、启动恢复及所有中断边界测试。

## 核验不等于授权

- `verify(destination, manifest_sha256, cancel)` 核对原始清单摘要、格式、路径／父目录关系、对象顺序、工作区摘要、实际对象集合和逐项字节。拒绝额外／缺失对象、未知字段、重复／乱序条目、链接、类型冲突和超限；数组在反序列化过程中就限制条目数，而不是先任意分配再检查。
- 此函数只证明对象完整性，不从清单自报的源路径、身份或版本授予生产接管。应用版本是来源元数据，不要求导出与核验程序版本号相同；格式版本和实际兼容规则才决定是否可读。
- `verify_receipt(destination, receipt, cancel)` 另核验真实目标目录身份及回执的每个摘要／数量／身份字段。逐字节复制的快照可以通过普通完整性检查，但不能通过原目录回执核验。前提仍是这个回执来自受控原生准备记录，而非从包中自行读取。
- 尚未实现恢复：正常交还应优先保留 Tauri 的当前兼容数据并反向交接草稿；只有明确选择灾难恢复才允许旧快照覆盖，并须按收纳原生日志处理真实文件移动，不能只回滚 JSON。

## 验证

- 定向运行：`cargo test --manifest-path src-tauri/Cargo.toml --lib managed_snapshot -- --test-threads=1`。
- 当前 17 项专项实际使用 Windows 本地临时目录和原生文件句柄，覆盖原始字节／资产／空目录／日志、运行锁排除、源与祖先固定、源新增、取消／撤权、检查点不符、目标不覆盖、物理路径别名、链接／junction、1 TiB 上限、对象损坏／缺失／多余、恶意清单／数组边界、跨应用版本元数据，以及复制目录不能冒充原生回执。
- 另有 12 项持久目录专项与 4 项真实工作区所有权／启动恢复测试。`npm run e2e:tauri:migration:snapshot` 构建双运行时并运行七项真实 Tauri 专项：原生文件夹取消／受保护选择、实际主窗与组件维护、原始 Data 与空目录／资产、原生回执、调用角色拒绝与伪造参数无效、真实硬链接失败的持久 pending→重启 abort，以及旧目标移动不阻断普通编辑。测试只操作隔离临时目录，须与其他原生／无窗口套件串行。
