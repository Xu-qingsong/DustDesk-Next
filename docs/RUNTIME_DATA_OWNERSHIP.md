# 运行 Data 可写所有权与真实工作区接入

## 当前范围

- 新增不可序列化的 `RuntimeOwner`，从当前存活 `FrozenSource` 与同 ID 的实际运行准备护栏消费构造。不是把原生回执 JSON 反序列化为许可，不提供任意路径或克隆目录的接管入口。
- 在释放输出文件的只读固定句柄之前，取得与准备 Electron／普通 Tauri 工作区相同的物理目录身份命名管道独占。输出根和全部祖先始终固定，原来源、快照、原 LAN 和原生记录继续持有。
- 真实 `WorkspaceStore` 已实现 `TryFrom<RuntimeOwner>`：采用已经取得的那一个原生所有权，不先释放再自行重取；保留原有工作区文件锁、原生草稿检查和正常存储恢复。实际原生业务代码已经验证加载、编辑、保存、关闭及恢复后读取新内容。
- 这是输出 Data 的真实可写所有权内核，仍不是 GUI 启动、原运行时／原 LAN 服务所有权移交、浏览器草稿导入或完整生产切换。没有新增公开业务 API、Electron 菜单或 stdio 启动命令，默认入口、版本和分支不变，不提交、推送或发布。

## 原生决定与句柄交接

- 每次尝试位于实际运行准备记录下的 `Ownership/<原生 UUID>/`，先发布并同步 `intent.json`，在全部当前来源／输出核验通过后发布不可逆 `decision.json`；绑定完整运行准备回执 SHA-256、运行准备 ID 和实际输出身份。
- 已有其他原生目录所有者时，在创建本轮意图及释放任何输出文件固定之前失败。已有成功授予不创建第二份许可，必须显式指定原 ID 恢复。
- 成功决定发布、实际原生记录重新固定且跨运行时独占仍在持有后，才释放输出文件与子目录的快照固定句柄。输出根、父链、原记录和全部原来源／快照护栏持续持有，不能出现先放开全部句柄再按路径获取锁的间隙。
- 授予后的输出是实际可变 Data，允许正常 `workspace.lock`、新资产和业务写入；旧运行准备清单不再被当作当前可变目录内容断言。原来源与快照依然不可变，迟到新增仍会撤销确认。
- 原生授予回执始终为 `productionReady: false`、`migrationComplete: false`。持久 Granted 表示曾完成授予，不表示某进程目前仍在运行；它本身也不是一个持有命名管道的活权限。

## 恢复与撤权

- 只有意图没有决定时，恢复仅持久标为 Aborted；即使输出完整，也不猜测授予。中止记录不覆盖或删除输出，重新完整核验后可以用新 UUID 重试。
- 已有成功授予时，`verify_runtime` 拒绝重放旧只读准备；即使尚未发生任何业务写入，也要求显式进入所有权恢复。
- 恢复先重新取得并完整核验原来源、快照、原运行准备与所有权决定，再核对原输出根及原父目录物理身份，重新取得真实目录独占。之后把已经合法变化的数据交给真实工作区存储读取，不用旧字节摘要否定正常新增编辑，也不默默回退到旧快照。
- 复制输出、替换父目录、错误授予 ID、篡改回执、原来源／快照失效或已有原生所有者均失败，保留决定和实际数据。缺少意图或出现未知记录内容仍保留并阻断，不自动清理或猜测成功。
- Rust 状态查询仅返回原生记录元数据，不固定可变输出，也不授予权限；本轮尚未增加对应 stdio 分页／启动通道。
- 活权限保留原取消令牌。原生工作区读写入口复核取消、原文件固定状态、来源与快照名称集合、原始 LAN 和原生记录；撤权后拒绝读取与保存，仍保留独占直到存储／权限对象实际释放。
- 常规存储操作不反复重读数百 MiB 的已零共享固定的旧版程序；完整哈希在准入／恢复及显式 `verify` 中完成，持续确认使用原句柄、物理身份、属性和完整名称集合。原有准备会话的完整确认语义没有放宽。
- 关闭后原来源不再被固定；如果旧运行时随后修改了原来源，本轮恢复会拒绝旧快照，保留新输出等待后续切换／恢复协议处理，不丢弃新编辑或伪造兼容成功。

## 浏览器来源授权（后续增量，未接 GUI）

- `RuntimeOwner::browser_archive` 直接从原组合快照中持续持有的那个浏览器归档文件句柄读取原始字节，不释放后按路径重开，也不读取可变输出中的同名文件。每 64 KiB 检查取消、执行有界读取，读取前后核对文件状态和完整摘要，并重核原生准备、原来源与所有权。返回值不可由 JSON 反序列化构造；原始文本保留原编码字节，临时缓冲在释放时清零。
- 真实 `WorkspaceStore` 的草稿来源核验仅在它实际持有 `RuntimeOwner` 时使用此原生来源：要求收到的归档与固定原始字节逐字节一致、原归档证明一致、工作区文件仍为原浏览器检查点，并在末尾再次确认当前原生所有权。来源命名空间使用该次原生授予 UUID，不把克隆的旧目录谱系改写为新目录授权。
- 普通工作区仍执行原有 `MigrationLineage` 物理根身份和导出回执核验；仅复制相同 Data、相同回执和相同工作区摘要不能走新路径。重新格式化归档、更换原检查点、正常业务修改后的旧归档和取消均不能获得本轮来源授权。
- 这只接通后续受控浏览器导入所需的原生来源核验及既有原生草稿事务准入，不声称已经写入 WebView2。GUI／新 profile 的持久绑定、受控导入与实际读回、启动屏障、客户端断连、整体切换和原 LAN 服务移交仍待完成。下列归档验证数字属于此前输出所有权增量，不代表本节变更的完整冻结回归。
