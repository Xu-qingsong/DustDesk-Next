# 存活来源与原生组合快照

## 当前范围

- 新增 `BoundSource::freeze` 和仅由存活对象构造的 `FrozenSource`，把正式旧代码固定、实际 Data 原始检查点、当前浏览器来源绑定与 `Frozen` LAN 原目录检查点接到同一原生准备链路。它不从序列化回执重新授予来源权限。
- 原生内核和专用 stdio 模式已接入准备 Electron 的独立原生菜单“准备旧来源组合快照（不切换）…”，串联实际浏览器读取、全部编辑器维护和原 LAN 停止／恢复。现有“从旧安装目录导出草稿…”仍仅导出 v1 草稿，不会静默改成组合快照。
- 这不是历史 profile 认证、整个安装目录执行安全认证、生产接管或正式切换。浏览器包必须由当前准备主进程在受控来源读取后交付；单独调用原生工具不能证明这些字节一定来自真实浏览器。

## 生命周期与物理固定

- `freeze` 消耗已有来源对象，在相同实际 userData 中获取跨 Electron／Rust 的物理 LAN 目录独占租约，再固定原始 `state.json`、`identity.json` 及其身份和摘要。实际 LAN 服务或写入者未释放时拒绝，不以暂停 UI 或布尔回执代替独占。
- 未初始化的 LAN 不创建目录或设备身份；准备期间出现目录或文件会使检查点失效。身份私钥留在原 profile，仅记录设备标识、证书指纹和原文件证明；状态按原字节复制，外部传输文件／分片仍须在原位置。
- 来源、LAN 与原工作区固定一直保持到准备决定落盘和最终确认结束。过程内取消、父通道 EOF、强制终止会释放原生句柄。复制前后重新散列来源；分块工作中以存活句柄、文件检查点及实际目录身份核对，不在每个分块反复散列整个旧 EXE。
- 新测试实际复现：已有只读工作区租约与快照扫描的零共享读取冲突，报 Windows `os error 32`。只对根 `workspace.json` 改用允许读取但拒绝写入／删除的固定句柄，其他源文件仍零共享；没有释放来源后重开、允许写入者或忽略错误。失败保留于 `artifacts/tauri-migration/live-source-snapshot/workspace-pin-before.log`。

## 持久决定与核验

- 原生目录固定为实际 userData 下 `LegacySnapshotPreparation/<Data卷标识>-<Data文件标识>`；复用现有物理目录绑定、独占目录锁、写前意图、组件摘要、成功决定和中断恢复，不能由 renderer 提供记录路径。
- 组合清单增加可选 `components.source`，由仍存活的 `BoundSource` 生成，组件摘要绑定到写前意图和持久回执。普通交接不写该字段，保留原有无来源字段的序列化和摘要语义。
- 静态核验检查来源元数据与 Data 源目录／原工作区身份和摘要、浏览器绑定及冻结 LAN 的对应关系。来源草稿必须标记为 Electron。序列化 `Binding` 只作证据，可解析或展示，不是可恢复的 `BoundSource`；校验和及自报字段本身不构成新的认证根。
- `verify_prepared` 必须重新取得同一实际来源与 LAN 的存活独占，再从原生目录核对已决定回执和全部内容，并精确匹配当前来源及原 LAN 检查点。替换 browser profile 或改变原 LAN 状态后，旧准备决定不能重新授予权限。
- 重开 `verify_prepared` 现在会在原生决定与目标内容核验后，重新枚举真实活源的完整非运行时 Data／资产并逐文件哈希，比较路径、身份、大小、时间、只读属性及空目录身份；成功后保留资产句柄到 helper 关闭，并在后续确认中重查目录集合，不能复用到其他准备 ID。仅工作区未变、原资产已变的旧决定会被拒绝，机制与专项见 [活源资产复核](LIVE_SOURCE_FRESHNESS.md)。
- 该护栏只在同一存活来源和全部编辑器维护中有效，helper 关闭后旧回执不再证明当前资产新鲜度。后续已在同一会话保留完整目标组合包、Data 对象和实际原生意图／决定，并用原句柄再次核验；但尚未贯穿真实生产切换／恢复／回退事务，不能把一次新鲜核验或原成功决定当作正式切换许可。见 [目标与原生决定保活](RETAINED_SNAPSHOT_TARGET.md)。
- 只有 Data 清单、只有 `handoff.json` 或复制了一部分目标都不构成成功。缺少外层成功决定的意图在受控恢复时记为 aborted，不自动提升、删除不完整目标或覆盖现有目录。原有成功决定也不等于已经切换生产数据。

## 专用通道

- `dustdesk-tauri.exe --legacy-source-snapshot-v1` 跳过普通 GUI／托盘启动；只有唯一参数进入此模式。原有 `--legacy-source-lease-v1` 保持只读，不能上传草稿或创建快照。
- 先用与来源租约相同的 v1 `open` 消息提交受信主进程实际路径和原工作区摘要，原生完成来源及 LAN 独占后返回 `ready`。所有后续消息使用同一个 UUID v4 请求 ID。
- `draftsBegin` 声明原始字节数及 SHA-256；`draftsChunk` 交付标准 Base64，每块最多 32 KiB 原始字节、逐块确认。总量最多 64 MiB；单条 JSON 行仍限 64 KiB，输入队列有界，不接受空块、越界、截断或摘要不符。
- `prepare` 只接受显式目标目录，原生拒绝旧安装、Data 或 userData 内目标和既有目标；每个会话最多准备一次。`verifyPrepared` 只接受原生记录 ID；`confirm` 和 `close` 维持租约语义。此私有通道不是同用户 OS 安全或提权边界，不向 renderer 或网络开放。

## Electron 维护入口

- 目录选择和警告确认后才进入维护。先等待真实主窗、快速记录和全部组件保存，再封存工作区；LAN 单独停止并排空已接纳操作，不清空图片工具箱资产。原 LAN 目录独占释放后才启动快照 helper；真实当前 Session 的受控旧 file URL 读取不执行旧安装代码。
- 主进程将实际白名单原文封装为 v1 草稿并记录原生谱系，再逐块交付原生组合准备；核验成功决定及目标物理身份后才显示成功。成功也明确标注“未切换”，输出不是独立身份／外部文件恢复包。
- 每次准备有独立取消信号和五分钟维护上限，文件及托盘菜单提供“取消来源快照准备”。取消、窗口失效或 helper 丢失后先等待实际原生操作及清理结束，再解除编辑器与写入门闩，最后恢复原 LAN 配置；正常退出请求在此期间只请求取消，不越过清理。
- 原维护超时曾提前解除门闩，现通过故障用例证明并修复。封存后的异步操作必须排空；未进入封存的旧等待保存／迟到 seal 仍使用原取消语义，避免无限等待未响应编辑器。需要持久恢复的原事务继续保留门闩，不被此改动自动解锁。
- 原生决定已经落盘但客户端随后取消时，不自动删除目标或抹去决定，不显示成功；错误通知明确指出可能存在已落盘决定。LAN 恢复错误会保留提示，不覆盖原操作错误或将完整恢复伪装成成功。
- 实测当前准备 Electron 的不同 file URL 会共享相同 Session 中的 localStorage；组件保存能更新旧来源 URL 随后读到的同名草稿。测试保留该事实并核验真实维护检查点字节，而不假设目录对应独立存储。这里证明当前 Session 的受控读取，不证明历史安装曾独立拥有这些数据；确认对话框明确提示这个边界。
