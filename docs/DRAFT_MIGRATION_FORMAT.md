# 浏览器草稿迁移格式与导入内核

## 状态与边界

- 本文描述共享格式和浏览器存储事务，不代表生产迁移入口已交付。Tauri 隔离预览已接通原生文件选择、预览确认、全窗口维护、本地回执核验、持久事务与编辑器重载；跨配置来源定位、生产快照与谱系移交、生产导入及反向回退仍未完成。
- 调用方必须先暂停所有共享该 origin 的编辑器并完成保存/草稿检查点，导入及恢复期间禁止创建或恢复其他编辑窗口。localStorage 的逐键操作不是跨 WebView 事务；此模块的同步写入不能替代原生排他门闩。
- SHA-256 用于发现损坏和内容改变，不是签名或来源认证。工作区 fingerprint 必须来自原生已确认的迁移快照/谱系，不能直接相信用户所选文件提供的 fingerprint。
- 不解析 Chromium LevelDB，不导出 Cookie、会话、令牌、缓存、LAN 私钥、任意 localStorage、既往导入日志或回执；正式入口必须使用原存储配置的受控页面读取白名单。

## Electron 准备构建导出

- 此构建的托盘菜单提供“导出迁移草稿…”；非打包开发构建的“文件”菜单也有相同入口。先在系统保存对话框选择 JSON 文件，再开始短暂维护；取消选择不会冻结编辑器。已发布旧版本不因此自动获得入口，本轮未发布准备构建。
- 主进程限定原生配置的应用入口 URL、实际主窗、相同 session 和相同页面路径，不能仅凭当前页面自报的 origin 判断来源。主窗、快速记录和所有实际组件分别保存并应答；应答绑定真实 WebContents 对象和随机请求，不以数字 ID、前端传入窗口标签或退出保存事件代替。
- 通过独立 drafts:flush / drafts:flushed 冻结输入、执行原有保存回调和排空在途写入。维护期间阻止主窗回收、快速记录回收、新组件创建及正常退出；工作区队列封存前允许保存回调落盘，封存后拒绝新工作区读写，剪贴板轮询不接受新样本。现有退出保存协议与维护协议互不消费确认，保存失败仍允许按旧方式重试。
- 在工作区变更队列内等候已接受的写入，读取实际 workspace.json 字节并计算 SHA-256，再同步封存队列。由真实主窗的隔离 preload 同步执行共享白名单采集，仅返回合法键值；其余窗口、旧请求、重复应答、坏值、未知草稿键版本或不一致存储来源不能完成检查点。
- 冻结与检查点采集阶段最多 35 秒；此前的文件选择及此后的不可变归档落盘不计入该时限，也不要求持续冻结编辑器。窗口重载、渲染进程退出、窗口销毁、保存异常、合成或实际 composition 进行中及维护超时均取消采集，并恢复仍存活的参与窗口。取消立即使会话失效，迟到的封存回调不能操作新会话。合成事件测试不代替物理输入法验收。
- 采集完成后立即恢复编辑；原生主进程仅使用已验证的不可变键值与对应文件摘要异步封装和落盘，不再异步读写已恢复的浏览器存储。导出对应的是采集时的检查点，不意味着后来编辑仍属于同一快照，也不意味着摘要已成为可信迁移谱系。
- 原生写出使用同目录随机临时文件、排他创建、刷盘后重命名；拒绝覆盖目录、符号链接、工作区和应用用户数据目录，父目录 junction 别名同样按 realpath 检查。失败不以部分包或截断数据充当成功。草稿包及检查点当前均限制 64 MiB，超限明确失败；完整历史规模兼容仍是切换门槛。
- 文件提交成功后的通知失败单独记录，不再误报“未导出”；原主窗已经回收时使用无父窗的结果通知，不因通知窗口失效否认已经完成的文件写出。
- 仅导出便签、任务输入、快速记录与必要选择状态，不包含工作区、附件、Cookie、令牌、缓存或局域网身份。原存储中的任何值都不因导出而删除。包不能单独用于生产切换；Tauri 隔离导入只接受当前已独占物理工作区及本地原生回执认可的包，不会因用户选择文件就信任其来源或接管生产目录。
- tests/electron-draft-export.mjs 启动真实 Electron、sandbox preload 和 file-origin 多窗口，通过实际菜单处理器导出真实文件，并验证失败恢复、重载、禁退出/新窗和保护源数据；测试替换文件选择/通知对话框的返回值，不声称已操作真实系统选择对话框。只证明当前原生认可的入口路径，不证明旧安装路径变化后的 origin 已受控读取；不会直接解析 LevelDB。

## Tauri 隔离预览原生导出

- 实际主页面提供“导出迁移草稿”。`drafts_export` 不接收 renderer 提供的路径、条目、包头、编号或预期指纹，独立权限只授予真实主窗。原生先显示 JSON 保存对话框，取消不创建维护检查点或回执；选中的目标必须位于应用内部数据目录之外。
- 原生通过既有全编辑器保存进入 Ready，再绑定实际 WebView profile/origin，直接 `eval_with_callback` 采集该主窗的白名单 localStorage。存在未恢复 pending、未知便签版本、非法字段、采集期间变化、超量或过期租约时拒绝发布；普通无关存储不导出也不删除。
- Rust 独立验证白名单、规范化的 encodeURIComponent 窗口所有者、UTF-16 字段长度及唯一键。保留原始 value JSON 的空白与转义；JSON 字段内的转义未配对代理字符也按 JavaScript 码元长度校验，不替换原文。原始键和选择状态仍须能由 Rust UTF-8 字符串表达；含未配对代理字符的 legacy ID／选择值会明确失败，尚不宣称任意 JavaScript UTF-16 标识均兼容。
- UUID、UTC 毫秒时间、应用版本、`runtime=tauri` 和工作区指纹均由原生生成／获取，沿用 browser-drafts v1。条目按 JavaScript UTF-16 键顺序排列，64 MiB／5000 项上限保持；不截断草稿。
- 持有组件门闩、工作区存储互斥和浏览器绑定，检查当前主窗、Ready 租约与旧进程排除，先暂存外部文件，再将原始归档／payload 摘要及检查点原子追加到当前物理工作区的 `MigrationLineage/lineage.json`，最后原子发布外部文件。旧 Electron 回执与 workspaceId 保留，坏／未知／重复／超量历史不重置。发布失败可能留下未使用的原生导出回执；回执存在本身不证明外部文件已经交付。
- 写盘或检查失败恢复编辑器且保留原目标；原生回执写入失败不得先覆盖外部文件。已成功提交文件和回执而维护收尾报错时返回明确 warning，不谎称没有文件。导出结束不重载编辑器，脏任务输入继续可编辑。
- 当前只完成反向迁移的导出前提。准备 Electron 的实际来源核验模块已能在 Tauri 正常退出释放目录后核验原始包；这不等于 Electron 已具备受控反向导入、持久决定、启动恢复、跨配置移交或生产回退。

## 同配置旧安装路径的受控读取

- 托盘和开发“文件”菜单提供“从旧安装目录导出草稿…”。选择旧安装根目录后，原生仅推导固定布局 resources/app.asar/out/renderer/index.html 的 file URL，不接受任意 URL、不运行所选目录下的 EXE，也不加载旧 HTML、JS 或 preload。文件选择取消时不进入维护。
- 该入口使用当前 Electron 主窗的实际 session 和用户数据配置。它不是任意用户或任意 Chromium profile 的浏览器存储提取器；目录选择不是来源认证，不凭目录名称证明数据身份。不同 file URL 是否共享存储由实际 Chromium 分区规则决定，不假设每个文件路径必有独立 localStorage。
- 先保存并冻结全部当前编辑器、封存工作区队列，再创建受限隐藏读取窗。它仍使用同一实际 session，在选定旧 file URL 下，由原生临时 file 协议处理器返回自有空 HTML，设置禁止脚本、连接、框架、表单等资源的 CSP；旧 ASAR 的页面正文和脚本不被拿来执行。其他文件请求通过 session.fetch 的 bypassCustomProtocolHandlers 委托给原协议，不递归进入临时处理器。
- 若 session 已有自定义 file 协议处理器，明确拒绝而非覆盖未知处理器。仅当本次成功安装处理器才卸载；正常完成、异常、读取窗销毁或父维护取消时销毁读取窗并恢复原文件协议，再允许当前编辑器恢复。读取窗自身最多等待 10 秒，仍受父维护 35 秒上限约束。
- 读取窗使用 sandbox、contextIsolation、禁用 Node integration 和 webview，并禁止页面导航、重定向和新窗。原生 additionalArguments 选择只读 preload 角色；该角色不执行桌面 API 安装函数、不暴露 window.dustdesk，仅有一次白名单读取的私有 IPC。没有公开调试端口或测试专用产品命令。
- 为避免多入口 Rollup 产生 sandbox 无法 require 的共享分块，仍构建一个自包含 preload/index.js，运行时按原生角色分别安装桌面或只读行为。两种角色共用实际 collectDrafts，不复制另一套白名单规则。测试装载器同步使用这份真实代码。
- 私有回复校验真实读取 WebContents、当前主 frame 的 processId/routingId/URL、原生随机令牌和维护有效性。其他窗口即使拿到真实令牌也不能替换结果。父维护的 AbortSignal 在恢复编辑前使读取权限失效；迟到的旧读取不能被新会话接纳。结果再次经过共享字段、容量、重复键及白名单校验。
- 未发现任何可识别草稿时明确提示不能确认已恢复，不把空包当作旧用户迁移完成。不会清理旧存储、合并覆盖当前草稿、导出 Cookie/缓存/令牌或解析 LevelDB；也不复制整个浏览器 profile。导出仍只是快照，不授予 Tauri 接管生产数据的权限。
- tests/electron-legacy-drafts.mjs 使用真实旧布局 ASAR 及同 profile 正常退出/重启后的持久存储；随后把旧 ASAR 换成会覆盖草稿、发网络请求和开新窗的恶意页面，再验证受控读取保留原始值且无请求。另覆盖既有协议保护、实际读取窗销毁后的恢复、携带真实令牌的外来 WebContents、取消及普通页面重载/导出。对话框返回值仍由测试夹具提供，不替代真实系统 UI 验收；报告 electron-legacy-drafts-native.json 明确 productionReady=false。
- 当前仅支持已知旧版打包布局及同一用户数据配置。其他安装布局、安装路径已完全不可定位、其他用户数据/profile 的受控定位与实际历史版本样本仍需验证；不能据此标记完整旧用户兼容、可信谱系或生产切换完成。

## Electron 原生持久回执基础

- Electron 成功采集受控来源的白名单并形成不可变归档后，先在实际已独占的 Data/MigrationLineage/lineage.json 记录本地回执，再写用户选择的外部草稿文件。草稿包仍为 version 1，字段不变；不会把本地 ledger、浏览器 profile、原始草稿正文、用户选择的导出路径或其他凭据装进包。
- ledger 的严格顶层字段为 format=dustdesk-draft-lineage、version=1、workspaceId、root 和 exports。workspaceId 是首次记录生成的 UUID v4；root 的 volume/file 为原生已打开工作区目录的 16 位小写十六进制卷号/file index，目录复制到其他物理身份不能直接继承此回执权限。
- 每条 exports 严格包含 archiveId、archiveSha256、payloadSha256、workspaceFingerprint、runtime、appVersion、createdAt。archiveSha256 绑定最终归档原始 UTF-8 字节，不只绑定包内 payload；workspaceFingerprint 来自已封存的原生检查点，而非用包内自述值作为预期来源。包在语义不变的情况下重新格式化，也不再匹配原生记录。ledger 不包含 entries 或草稿正文。
- 记录和验证均要求当前实际目录独占权限仍有效；读取只认上述固定原生路径，拒绝链接/junction、非普通文件、多硬链接、无效根身份、未知/未来版本、额外字段、重复 archiveId 及坏回执。同一 archiveId/原始包重复记录幂等，内容不同时拒绝。缺失回执不授权导入，损坏记录不重置、不自动从用户包重建；如果整个 ledger 被删除后重新导出，会生成新的身份，旧归档不会自动恢复信任。
- 写入按所有权对象串行化；同目录临时文件以 wx 创建、数据 sync 后提交。首次通过不覆盖的硬链接发布并移除临时链接，后续用 rename 替换现有有效文件，不先删除旧 ledger；提交前重读并比较前一有效记录。读取最多 8 MiB，历史最多 4096 条，超限明确拒绝、不偷偷清理。失败或中断可能留下未用于外部导出的回执/临时文件；临时文件不被当作权威，初次发布途中留下多硬链接时会拒绝而非自动修复，需要补充受控恢复验收。
- 原生记录先于外部导出，故外部目标写入失败时可能存在没有外部文件的回执，这不等于导出成功或迁移完成。相反，ledger 写入失败时不会覆盖先前外部归档。普通工作区在导出后可继续编辑，回执只绑定采集时的检查点，不能由此推定当前数据和附件仍属于同一快照。
- 正常退出在采集/维护阶段仍拒绝进入；已取得不可变草稿后的封装、ledger 和外部文件写入阶段允许进入退出保存流程，并等待在途原生写入完成。等待最多 15 秒，失败或超时取消退出并恢复编辑，不强制中断尚在进行的文件操作；结果通知不加入写入等待，避免把用户未关闭的通知当作未落盘。真实测试在主进程延迟 rename 调用，验证短暂阻塞时等待后退出，以及长时间阻塞时取消退出、草稿保留、解除阻塞后原导出继续完成，不冒充物理磁盘满或硬件 I/O 挂起验收。
- tests/draft-lineage.test.mjs 覆盖重取所有权后的验证、未登记/伪造/重新格式化归档拒绝、目录复制拒绝、并发追加、坏/未来/重复记录不重置、硬链接/junction、锁释放/路径阻塞及历史上限。真实 Electron 导出套件核对原始包摘要、ledger 损坏阻断和正常退出/重启后保留 workspaceId 并追加新回执；文件 symlink 创建在当前测试账户无权限，没有把它写成实际系统验收通过。
- 这是由可信原生路径和现有用户文件权限约束的本地记录，不是签名、跨机器证书、对抗同账户恶意修改的认证或远端真实性证明。Electron 写入与 Rust 当前目录只读核验已接通；生产源目录和快照绑定、跨目录受控移交、原子导入与反向回执仍需实现，不能让 renderer 或用户所选 ledger 文件自我授权。生产迁移入口继续关闭。

## Rust 当前目录只读核验

- drafts_verify 仅授予实际 workspace-main，由独立 draft-verifier 权限配置及 Rust 当前窗口身份复核共同限制；原型窗和组件无权限。调用只接收维护 requestId 和原始归档字符串，不接收来源路径、ledger 或预期 fingerprint。
- 核验在原生组件门闩及工作区存储队列内执行，只使用当前已独占根目录固定 MigrationLineage/lineage.json。复核持有句柄与当前目录的 volume/file 身份，拒绝重解析点、非普通文件和多硬链接；ledger 最多 8 MiB、4096 条，归档最多 64 MiB、5000 个 entries，未知/重复/未来/损坏记录只拒绝、不重置或修复。
- 先以完整原始 UTF-8 字节 SHA-256 匹配原生回执，再检查 payload 摘要及来源头字段；当前 workspace.json 原始字节也必须仍等于本次 Ready 封存摘要，语义相同的重新格式化也拒绝。加载合法工作区时规范化保留无需改变的整数表示，不能为了通过核验而放宽为语义摘要或改写回执。
- Ready 请求、取消状态及实际单调时钟截止时间在工作前后均复核；不依赖后台超时任务是否已获得门闩，也不允许复用已结束请求。核验前后同时复核标准旧进程已停止，迟到的异步结果不能恢复过期权限。
- 返回 workspaceId、archiveId、archiveSha256、workspaceFingerprint 和 sourceRuntime，仅是当前本地记录的只读检查结果，不是后续写入令牌。该 Rust 检查只验证归档来源头及 entries 数量，不代替共享内核的逐项草稿白名单/冲突校验；不写 localStorage、不导入、不修改 ledger，不授予任意后续异步存储操作权限。
- tests/tauri-draft-lineage.mjs 先由真实 Electron 原生菜单导出并正常退出，再由 Tauri 打开同一隔离物理目录。验证原始字节、角色、Ready/过期/重启、伪造参数、坏记录、真实硬链接/junction 和工作区变更拒绝，并检查目标草稿仍为空；该同目录夹具不证明生产源发现或跨目录迁移已完成。

## 跨运行时工作区所有权

- Windows 使用目录的原生卷序列号及 64 位 file index 作为身份；Node 从打开的目录句柄读取 bigint dev/ino，Rust 从目录句柄调用 GetFileInformationByHandle。管道名为 \\.\pipe\dustdesk-workspace-v1-<16位小写十六进制卷号>-<16位小写十六进制文件号>。不以路径字符串、版本号、浏览器 profile 或 renderer 提供的标识判断同一目录；大小写及已规范化的路径别名不能绕过锁。
- Electron 在首次 readState、IPC 注册、收纳恢复、后台服务和窗口创建前取得管道监听所有权，并由主进程持有至终止；readState 额外拒绝未取得所有权的调用。目录句柄身份无效、符号链接/junction、加锁期间身份改变、管道占用或权限失败均拒绝启动，不自动删除锁、不只弹提示后继续服务。锁不通过 renderer API 暴露。
- Rust WorkspaceStore 在打开工作区数据与原有 workspace.lock 前创建带 FILE_FLAG_FIRST_PIPE_INSTANCE、单实例和拒绝远程客户标志的同名管道，并持有目录句柄及管道到 store 释放；目录句柄不共享删除权限，持锁期间不能重命名该目录。保留已有 fs2 文件锁，后者不被当作 Node 也能识别的跨运行时协议。
- 该管道仅用于排他，不提供迁移数据或控制命令；Electron 收到连接即关闭。内核随所有者进程终止释放，不依赖 PID 复用、定时过期或手工移除 workspace.lock。独立目录不互相阻塞。
- tests/workspace-ownership-native.mjs 覆盖实际 Electron 启动持锁、不同 profile 的 Electron 启动拒绝且工作区字节不变、Node 先持锁时实际 Tauri 拒绝初始化、释放后 Tauri 接管并阻止 Node，以及两进程终止后可重新持锁。系统错误对话框由夹具替换以验证拒绝路径，不声称实际人工操作；所有数据在独立临时目录。
- 当前只验证本机 Windows 文件系统及识别协议的新构建。未知旧版不会遵守管道锁，标准产品名的额外检测见后文，任意改名/通用 Electron 旧进程的定位和明确退出门槛仍需补充；其他用户会话/网络卷、Electron 持锁后恶意替换目录或上级路径的防护也未完成。管道所有权不认证草稿包、不产生可信持久谱系、不授权生产目录切换，也不代替原生维护租约内的原子导入。生产入口继续关闭。

## 不识别新锁的标准旧版本进程

- Windows 原生 Tool Help 进程快照检测 DustDesk.exe、DustDesk.Next.exe 和 dustdesk-tauri.exe，按 ASCII 大小写不敏感的完整名称匹配，仅排除当前原生进程 PID。其他路径或用户数据配置下的同名进程也保守拒绝，不因认为其“应该是另一个 profile”而跳过；通用 electron.exe、WebView2 和仅包含 DustDesk 字符串的名称不误判。没有读取所有进程命令行、用户资料或私钥。
- 准备维护前先检测，失败不创建维护会话、不冻结编辑器。实际全部窗口保存应答、队列排空后，在封存工作区前重新检测；此时才出现的旧进程导致正常取消维护并恢复所有参与窗口。Ready 状态每秒重新检测，发现旧版重启或快照查询失败时撤销该 requestId、释放剪贴板暂停并恢复编辑，迟到的旧令牌不能结束或授权新会话。原有 120 秒租约到期任务独立保留，不用轮询替代超时。
- CreateToolhelp32Snapshot、Process32FirstW、Process32NextW 的非正常终止错误均导致拒绝；清单超过 65536 条或名称无终止符同样拒绝，不把部分扫描当成完整结果。快照句柄由 RAII 关闭；只向错误提示列出最多 8 个匹配进程的名称/PID及匹配总数。不会结束、关闭、挂起其他程序或发送退出命令，用户须从旧版托盘完整退出后重试。
- tests/tauri-legacy-processes.mjs 使用 rustc 编译独立 stdin 等待器，再以固定产品名启动真实进程；这些夹具不识别命名管道锁，不运行用户旧安装或访问用户数据。验证初始拒绝、大小写/历史命名、其他 Tauri PID、通用 Electron/相似名称不误判、全窗口保存中出现及 Ready 后重启、自动取消后重试与旧令牌失效。
- 这是保守的进程存在检测，不是可执行文件签名或工作区谱系认证；同名其他应用可能被保守阻止，任意改名或通用 Electron 承载的未知旧版本尚不能据此排除。每秒轮询不是原子导入授权，短暂进程可能落在轮询间隔内；未来原生导入提交和生产接管必须再次检测并核实来源/独占边界。没有产品导入提交前不能宣称生产数据安全接管，实际跨用户会话及旧版安装样本也需补充验收。

## Tauri 原生维护检查点

- 由真实当前 workspace-main 直接调用内部 drafts_prepare，不通过参与保存排空的 tracked 队列调用，否则会让检查点等待自身。组件和原型无准备或结束权限。
- 原生持组件/主窗共用门闩登记实际参与窗口，进入独立维护保存状态，禁止新交互和退出；通过 drafts:flush 让主窗及所有实际组件冻结交互、执行现有保存回调并排空在途工作。准备时允许这些正常保存，封存后工作区队列拒绝新读写和备份操作。
- 每个窗口通过 drafts_checkpoint_ready 仅应答自己的随机请求一次；退出确认不能代替维护确认，旧请求、外来窗口和重复应答均拒绝。组件仅通过其原生私有 SDK Channel 接收维护事件，不开放通用事件监听/发送权限。
- 原生等待全部应答、提交布局、暂停并排空剪贴板后，在工作区存储互斥锁内读取并验证实际文件、计算 SHA-256 并封存维护状态。返回 requestId、workspaceFingerprint 和 leaseMilliseconds。失败保存不能因最后一个 pending 项被移除而误被封存。
- 真实主窗用 drafts_end 结束匹配的 Ready 请求；旧令牌不能结束新请求。默认 Ready 租约 120 秒，过期自动恢复操作；参与页面重载、窗口销毁、保存失败、输入法组合中或准备超时都会取消维护并恢复其他参与者。Ready 不等于退出提交，不能授权进程退出。
- 该原生文件摘要只是当前隔离检查点内容，不是持久谱系认证，也不是 archive 来源认证。隔离导入使用同步屏障暂存，异步校验后复核维护状态，原生在 begin 与决定提交时再次核对租约、来源和独占；单次前置查询不能代替最终原生提交边界，全部时序与生产接管仍需验收。
- Debug 且启用隔离测试根时可缩短租约进行验证；Release 和普通启动固定使用生产时限。测试报告 draft-maintenance-native.json 明确 productionReady=false。

## Electron 反向事务内核与异运行时阻断（准备构建）

- `src/main/draftTransaction.ts` 是仅供原生主进程调用的持久事务内核，当前尚未接入 Electron 产品入口、真实 profile 绑定、维护或启动恢复。Node 专项使用真实 Windows 目录所有权与文件、内存浏览器夹具；不能把此内核测试称为 Electron 反向导入已经交付。
- 开始前核验当前物理目录、工作区原始字节、本地来源回执、Tauri 前次事务完成状态和目标快照。共享规则仅在原生内存影子上计算精确计划，先刷盘不可变的 `ElectronMigrationJournals/<transactionId>.json`，再发布固定 `ElectronMigrationTransaction.json` 的 pending 元数据；真实浏览器暂存必须发生在其后。元数据记录日志／键摘要，不包含草稿正文。
- 原生观察到实际 pending 原文和每个暂存值匹配、维护请求仍有效且工作区未改变，才可落盘 commit；过期请求只能 abort，持久终态不可反向更改。恢复使用该事务独立的原生副本，缺失／改变副本、错误浏览器绑定、冲突回执和孤立浏览器日志阻断；pending 在恢复时先持久决定 abort，再撤销尚未改变的暂存值。
- 原生结果复核闭包绑定本次原始记录，确认浏览器日志已清理、回执及实际键值满足决定后，才持久 completed。所有排队调用在入口复制观察快照，不能被后续异步修改参数改变决定依据；completed commit 不复活已消费输入，completed abort 且无 pending 时不重放旧回滚副本，后来重新输入的相同原文必须保留。
- 当前 Tauri 在创建 `workspace.lock`、打开编辑器或恢复服务前检查固定 Electron 元数据：pending、未完成 commit／abort、损坏／未来格式、目录身份不匹配、缺少绑定或载荷摘要、未知字段和多链接记录均保留并拒绝启动。合法 completed 记录允许正常启动；Tauri 不尝试替 Electron 恢复其浏览器。
- 内核首次发布使用排他临时文件、刷盘及不覆盖硬链接，替换时比较原始代次再原子改名；失败保留原始决定，不清除只读属性或重置记录。不代表物理断电下全部文件系统边界已经验收；首次链接后清理前中断等多链接现场仍会保守阻断，自动修复和历史归档尚未实现。

## 封装

- 外层仅允许 format、version、payload、sha256 四个字段；format 为 dustdesk-browser-drafts，version 为 1。
- payload 是 UTF-8 JSON 文本的字符串，sha256 为该字符串 UTF-8 字节的 SHA-256 小写十六进制。摘要计算基于原始 payload，不重新排序字段、不重新编码 JSON 后再校验，避免不同运行时的转义差异。
- payload 仅含 id、createdAt、source、entries。id 为导出编号；createdAt 是毫秒精度 UTC ISO 时间；source 仅含 runtime（electron 或 tauri）、appVersion、workspaceFingerprint；entries 是 key/value 原始字符串列表。
- 版本、来源、字段形状、摘要、重复键、工作区来源与各内容长度全部检查通过后才进入目标存储。未知字段/未知键/错误版本不是忽略处理，而是拒绝，避免误把未识别数据当完成迁移。

## 白名单与兼容

- widget-note:<id>：旧版便签私有草稿，保留原始 JSON。
- widget-note:v2:<编码的窗口角色>:<编码的便签 ID>：窗口角色仅 notes 或 note:<同一 ID>，要求规范 encodeURIComponent 编码，不将任意组件角色当便签。
- 便签值为 title、text、previousTitle、previousText 四字段；干净检查点为仅含 saved=true 的对象。必须保留干净检查点，防止旧 legacy 草稿在下一次读取时复活。
- widget-task-draft:v1:todo：title 与 requestId；requestId 不重建，保持成功提交后的去重语义。
- quick-capture-draft：kind、title、text 及可选 requestId；兼容更早缺 requestId 的值，实际受控检查点应先让原编辑器完成其正常升级。
- widget-notes:selected：原始选中 ID，允许空字符串。不凭选择键创建已删除便签。
- 标题上限 300 UTF-16 单元，正文/前文各 200000；requestId 上限 128，ID 上限 256。拒绝控制字符 ID、未知版本便签键和跨 ID 的窗口角色。
- 包总量上限 64 MiB、最多 5000 项；超限明确失败，不截断。累计长度在生成整包前检查。该阶段限制不应被描述成任意历史规模均兼容；若真实旧数据超限，切换前必须补充有界分包方案。

## 不覆盖与重复导入

- 目标已有同键时一律保留，包括空草稿与 saved=true；不以“看上去干净”推断可覆盖。
- 同一便签的旧 legacy 键与任一新窗口键存在优先级关系，因此目标存在任一对应 alias 时跳过冲突来源；notes 与 note:<id> 的两个独立私有草稿可以同时存在。
- 导入不写正式工作区，不创建任务或便签。已删除对象对应的历史草稿只能保留为待恢复内容，不能绕过正常业务的删除/冲突保护。
- 完成回执以导出编号与摘要标识；同包再次导入不补回已清理内容，不覆盖后来新草稿。同编号不同内容明确拒绝。
- 回执最多 4096 项；达到上限拒绝继续，而非删除旧回执后允许历史包复活。正式维护入口后续需提供保守的归档策略。

## 导入与恢复

1. 校验完整包及可信工作区谱系，再恢复前次遗留事务；无效目标白名单值、无效日志或回执阻止继续，不静默覆盖。
2. 记录完整待写键值到 dustdesk:draft-migration:pending:v1，再写此前不存在的目标键；每键写入前再次检查未出现新内容。
3. 所有键成功后提交 dustdesk:draft-migration:receipts:v1 回执，最后移除 pending 日志。回执是完成边界。
4. 回执前失败则回滚本次写入；仅删除仍精确等于本次导入值的键，后来改变的内容保留。回滚失败保留日志并明确禁止切换。
5. 重启恢复时，有匹配回执只清理日志，不回滚已完成导入；没有回执则撤销仍未改变的部分写入。不吞掉日志清理错误。

## 可暂存的同步提交内核

- prepareDraftImport 仅异步校验归档摘要、完整白名单与预期工作区摘要，不访问目标存储；返回冻结的准备对象，内部已验证 payload 不暴露给调用方修改。准备对象和其中的摘要都不是原生来源证明或写入权限。
- stage(storage, isActive) 同步恢复旧日志、检查目标冲突、写 pending 日志并暂存此前不存在的草稿键，但不写完成回执。暂存键已经可见，调用方必须在开始前暂停所有同 origin 编辑器，并持续持有原生排他屏障，直到提交或安全恢复完成；不能把 stage 返回当作可恢复编辑器的完成信号。
- isActive 必须同步、明确返回 true；false、undefined、字符串或 Promise 不能授权。首次存储操作、日志发布前、每个草稿写入前和最终回执写入前均检查。该回调只是进程内保护机制，不能把 renderer 自报 true 视作原生维护租约或一次只读 drafts_verify 的延长授权。
- commit() 和 rollback() 都是同步操作。commit 复核原始 pending 字节、回执历史、当前进程内事务身份、全部暂存值和新出现的旧格式 alias，再写完成回执、清理日志；所有异步来源核验及原生最终决策必须在调用前完成，不能在回执写入阶段再 await。回执成功后的日志清理失败不撤销已经提交的数据，后续恢复按既有回执处理。
- 同一 Storage 对象不能同时开启两个暂存事务；显式 recoverDraftImport 会使旧句柄失效，即使后续重试产生完全相同的 pending 字符串，旧 commit/rollback 也不能操作新事务。不同 WebView 的 Storage 对象不是同一个对象，这项内存保护不代替跨 WebView 原生门闩。
- 过期/取消、暂存内容/alias 或回执变化导致提交失败时，仅删除仍精确等于本次写入的值，保留后来编辑和外部有效回执。pending 被替换、存储不可读或回滚失败时禁止切换、不覆盖其他事务日志；解除存储故障后允许显式恢复/重试，不留下永久的进程内事务锁。
- 既有 importDraftArchive 复用 prepare → stage → commit 的即时包装，供共享格式/存储验证使用，不是生产导入入口。原生链使用真实 WebView 观察、持久草稿副本、不可逆决定与 recoverNativeDraftImport 恢复，再由原生复核结果；不能用即时包装绕过原生决定。完整产品工作流及所有故障时序仍需验收，不能据此开启生产迁移。

## 原生持久决定、浏览器绑定与启动恢复

- 当前隔离运行时使用固定工作区根目录 MigrationTransaction.json，严格记录原生请求/事务/工作区/归档 ID、目录身份、原始归档与检查点摘要、journalSha256、browserBinding、payloadSha256、逐键 SHA-256、decision 和 completed。元数据限 16 MiB/5000 键，不存草稿原文；旧预览记录缺少浏览器绑定时保留并拒绝自动恢复。UUID、摘要、字段、普通文件及单硬链接检查继续有效，坏/未来/未知文件不重置。
- drafts_transaction 与 drafts_recovery 只授予真实 workspace-main 的独立 draft-transaction 权限，不混入通用 workspace 或组件权限。原生检查当前窗口对象、固定 /tauri.html 主入口及实际 WebView2 目录；通过持有目录句柄取得物理卷/file 身份，并与原生 URL origin 一起计算 browserBinding，不接受前端自报 profile、路径或 origin。
- 开始必须处于实际 Ready：原生 eval_with_callback 从该真实主 WebView 直接读取固定 pending/receipts 键，不接受前端传入日志正文充当观察结果。原始 pending SHA-256、归档 ID/payload 摘要、唯一 writes 和每个原始键值均须属于已由本地谱系核验的原始归档；先校验再发布，不匹配不留下半个原生事务。后续提交也复核原生日志副本摘要和当前工作区原始字节。
- 浏览器 localStorage 的同步应答不是刷盘证明。实际原生进程树结束/重启测试发现浏览器 pending/键可能尚未落盘，不能靠等待固定时间绕过。现将真实日志原文先写固定 MigrationBrowserJournal.json，排他临时文件、sync_all 后发布，再持久化 pending 决定。该副本最多 64 MiB，含原始草稿正文，只留本地工作区，不放入日志、遥测或对外包；它不是可由用户选取的授权文件。
- 两个原生文件都先检查固定目录和文件安全性，首次用不覆盖硬链接发布、移除临时链接，后续复核已有文件后 write-through 替换，不先删除有效数据。副本先于记录的中断可能留下孤立副本，只有记录的精确摘要和浏览器身份能引用它；临时文件及单独副本不授权恢复。首次发布中断留下多硬链接时仍拒绝，需要受控处理，不自动删除记录或放宽链接检查。
- 决定为 pending → commit 或 pending → abort，终态不反转。原生会话互斥在最终边界复核真实截止时间、取消状态、检查点和标准旧进程；无有效会话、重启或过期只能把未决定事务变成 abort。commit 是原生持久决定，不等于浏览器完成；I/O/摘要失败不伪报成功。
- 启动在安装事件传输和挂载主 App 前执行受控恢复；普通读写、组件布局及后台恢复在未完成或新进程尚未重新验证浏览器确认时阻断。原生读取真实 pending、回执和已绑定键，核对 profile 与日志；共享 recoverNativeDraftImport 同步执行该终态。commit 保留/补齐暂存键、写完成回执再清日志；abort 只删除仍等于本次原始值的键，保留后来改动。
- 浏览器缺失日志或键时，可由精确匹配的原生日志副本恢复；已有不同内容或旧格式 alias 冲突时不覆盖。已有但被改变的浏览器日志拒绝，不用原生副本强行替换。不可逆 commit 的写入/清理失败保留日志和决定供重试，不调用普通失败回滚撤销已决定提交。
- finish 请求不是前端“已恢复”声明：原生再次 eval 真实存储，必须看到 pending 已清、commit 回执匹配且每个暂存键仍是预期值，或 abort 无完成回执且没有残留未改变的导入值。满足后持久化 completed，才解除当前维护屏障；完成记录保留、不删除原始权威。布尔 acknowledged/recovered/clear 不能跳过这些检查。
- 每次新进程都重新核对 completed 记录。若浏览器完成应答也未落盘，可由保留的原生决定和副本再次恢复；若原完成回执仍在，尊重之后已消费或修改的草稿，不重新应用原包。完成后的记录/副本只保留最近一笔，下一有效事务按顺序替换；历史整理、损坏记录人工恢复和大规模边界仍需补充验收。
- 没有对应原生记录的孤立浏览器 pending 会在主编辑器启动前阻断并保留，新组件页面也拒绝带 pending 启动；不从包或副本猜测决定。隔离文件选择/预览确认/导入已接通，但孤立日志用户恢复、全部故障时序与生产源/一致快照移交/反向回退仍未交付，不能算作可发布生产迁移入口。
- tests/tauri-draft-transaction.mjs 使用真实 Electron 导出和正常退出，Tauri 真实维护/暂存/原生决定及进程树结束后的自动恢复，覆盖 commit、abort、过期、未决定、日志/键丢失、完成应答丢失、已消费不复活、被改原生日志和不同物理 profile；被改浏览器日志在同进程真实渲染器重载验证，避免假设损坏写入已刷盘。它不是物理断电、恶意同账户文件篡改认证或生产 profile 切换验收。

### 隔离产品导入

- 原生单文件对话框选取 JSON，有界读取 UTF-8 原文与文件名，不接受 renderer 源路径或授予通用读取权限。拒绝空文件、目录、重解析点、多硬链接、无效 UTF-8 与超过 64 MiB 的文件，复核原生文件身份；选择/预览取消不进入维护。

### 启动与其他覆盖

- 原生事务记录存在时，启动协调器先创建同物理 profile 与 origin 的隐藏 workspace-recovery 页面，只授予 drafts_recovery 与 drafts_startup_done，不授予普通工作区、窗口管理或事件权限。原生重新读取实际存储验证完成，销毁工作页后才恢复后台服务与组件；workspace-main 等待该状态后才安装业务事件和编辑器。无记录的托盘启动不额外创建 WebView，因此不能提前发现仅存于浏览器的孤立 pending；该场景仍由主编辑器检查阻断。
- 恢复失败或工作页关闭时保持阻断，日志不清理，主窗口可显式重试；45 秒看门狗与窗口销毁绑定当前恢复代次，旧代次不得取消新恢复。原生验证后进入收尾状态，超时/销毁回调不能把已验证收尾反转为失败；销毁失败不放行启动。真实原生回归覆盖无主窗 commit/abort 后零 WebView 子进程、直接恢复可见任务组件，以及修复损坏原生日志后的显式失败/成功重试，不代表全部机器故障或生产接管验收。
