# 存活来源的完整资产复核

## 当前能力

- 来源快照的 `verify_prepared` 现在会从原生持久成功决定取得已核验的 Data 清单，重新枚举真实存活 Data，并逐文件复核完整 SHA-256、物理身份、大小、最后写入时间及只读属性，核对全部路径、类型和空目录身份。不再仅凭原 `workspace.json` 未变接受旧准备记录。
- 资产内容即使保持同一文件身份、同一大小并恢复原最后写入时间，也必须通过完整内容摘要；新增、缺失、替换、大小写改名、文件／目录换型和空目录替换均拒绝。失败不改写成功决定、删除快照或回写活源。
- 这仍不是生产切换许可。本节记录存活会话内的完整源检查点；后续已补齐同会话的完整目标与原生决定保活，但尚未贯穿一次实际切换事务，生产接管、完整回退、可信 helper 分发和历史 profile 归属仍未完成。默认入口和版本不变。见 [目标与原生决定保活](RETAINED_SNAPSHOT_TARGET.md)。

## 存活权限与资源

- 新增私有 `SourceInventory`，由原生来源对象与持久决定中已认证的实际目标清单构造，不从 renderer、自报校验和或序列化 `Binding` 恢复权限。该类型不能序列化、反序列化或克隆成新来源权限。
- 外层组合核验向同一原生调用返回已经核验过的内层 Data 清单，避免为了构造活源护栏重复读取／哈希整份目标。普通 Data／交接快照的公开核验返回和既有序列化格式不变。
- 枚举开始固定全部真实文件和目录；业务资产沿用零共享读取，拒绝现有读者／写者冲突及后续写入、删除或改名。只有根 `workspace.json` 使用已有允许读取、拒绝写入／删除的共享读取方式，与实际准备 Electron 的原工作区租约组合，不提前释放来源。
- `FrozenSource` 在成功 `verify_prepared` 后保留全部资产句柄至关闭；后续 `confirm` 复核目录集合、物理身份和文件元数据，不能把“原文件均被固定”误当成“目录不会新增文件”。每次再次 `verify_prepared` 重新哈希原固定句柄，不释放后重开资产，也不会与自己的零共享句柄冲突。
- 一个已固定的来源会话仅绑定同一原生准备 ID 和完整回执；不能换 ID 复用或在固定资产后新建另一准备。释放 helper 后文件重新可写，旧回执不保留活源新鲜度权限；下次使用必须重新取得正式代码、Data、实际 Session／profile、原 LAN 独占和完整资产护栏。
- 新活源枚举和 SHA-256 循环按目录条目及每个 64 KiB 读取块检查取消和实际来源授权。沿用 65536 条目、路径总量 4 MiB、128 层和总数据 1 TiB 上限，超限拒绝不截断，不把整份资产读入内存。失败或进程退出释放部分／全部资产句柄；原 LAN 和正式代码仍贯穿同一存活来源。
- 运行锁仅沿用根 `workspace.lock` 的已有排除语义，锁正文不作为业务资产、身份认证或迁移权限。不同 file URL 仍可能共享当前准备 Session 存储；完整资产护栏不增加历史 profile 认证，也不建立本机同用户进程的安全隔离边界。

## 证据与剩余门槛

- 修改前两项确定性回归均失败：只改资产而工作区不变时，重开 `verify_prepared` 仍接受旧决定；核验成功后可以立即打开原资产写句柄。原始结果保留于 `artifacts/tauri-migration/live-source-freshness/before.log`，原先九项来源快照检查仍通过，不能把缺口解释成旧准备决定或工作区认证已经损坏。
- 十项清单专项覆盖原始文件／空目录保留、八种资产变化、同大小／同时间摘要伪装、实际写者冲突、枚举后新增、固定后新增、完整哈希中取消／授权丢失、只读变化、运行锁排除和失败释放。另两项存活来源回归覆盖重开旧决定拒绝变更资产及保留句柄、同 ID 重验、跨 ID／再次准备拒绝和关闭释放。
- 原生来源套件增加精确正式参考字节下的变更资产、额外文件、空目录身份变化拒绝及固定后新增撤销，检查原决定／目标不被重写。真实 Electron 套件在原生 `verifiedPrepared` 已输出、客户端尚未处理响应前直接探测原资产写句柄，随后验证 helper 关闭后恢复可写及原服务／编辑器恢复；系统对话框仍仅在隔离测试进程中替换，LAN 仍为回环限定。
