# Electron 维护会话中的原 LAN 隔离运行

本增量连接准备 Electron 的真实维护会话与同进程 Tauri 宿主。仅供 Debug 专用 TEMP 数据验证，不是生产切换许可；整体工作区／浏览器交还、完整回退和发布验收继续待办。

## 开发入口

- “文件 → 验证原 LAN 隔离交接（开发临时数据）”先保存并冻结全部编辑器，排空原 Electron LAN，再沿用可信来源组合快照、运行 Data 授予和实际 WebView2 草稿导入。
- 原“验证隔离运行交接”继续只验证草稿，不启动新宿主 LAN。新增入口必须由用户单独选择；打包构建无此菜单，原生也独立拒绝生产目录。
- 已启用且已初始化的原 LAN 由新宿主采用相同设备身份和当前状态，启动真实 HTTPS 接收／发送服务及发现；配对、每次接收和目录选择使用 Windows 原生确认。接收目录限制为本次专用临时根，目录存储拒绝父级路径、重解析点和非本地盘。
- 原 LAN 未初始化或关闭时，新宿主保持关闭，不创建身份、不监听网络；草稿导入不等于业务开放。

## 持久屏障与退出

- Electron 在发送 `startOriginalLan` 前，以不可覆盖发布方式刷盘 `<userData>/OriginalLanPreview.json`，绑定本次请求、准备、运行、所有权、实际来源目录和原工作区摘要。该文件只充当重启屏障，不提供原生权限。
- 屏障存在时，正常工作区读写／规范化和旧 LAN 创建／恢复均被拒绝。异常退出后不会靠内存维护状态或“子进程已关闭”推断交还。
- 正常结束、菜单取消或 Electron 通道 EOF 先停止准入，再等待真实网络、发现、接收／发送／文件工作和 Windows 确认队列结束。EOF 不提前撤销最终保存所需的原生所有权。
- 服务排空后持久记录 LAN 专用交还，保留最新状态、原身份和原快照；宿主发送绑定证明。Electron 必须观察真实 `close`、成功退出码和证明，重新核验物理目录／文件身份、文件大小和 SHA-256，才删除屏障。缺失证明、超时、强制终止或文件变化均保留屏障。

## 显式恢复

- “恢复原 LAN 交还（开发临时数据）”使用当前工作区独占和原摘要，启动新的受控原生来源会话。正常启动检测到屏障时，在创建编辑器、草稿恢复和后台服务之前提供“退出并保留记录”或“核验交还后启动”。
- 从未开始交接且原检查点完全匹配时，原生证明未启动；空交接目录或只有合法意图时，持久发布 `aborted.json`，不授予服务。该决定可重复核验且不覆盖旧记录。
- 已有完整原授予但尚未交还时，恢复最新状态并运行真实串行工作线程的重启／最终保存，不开启网络监听，再完成持久交还。有交还意图或完成决定时，仅按已有原生记录继续交还，禁止恢复为可写网络服务。
- 未知内容、孤立决定、改变的意图／中止记录、原工作区或物理身份不匹配均保持阻断，不删除记录、不回放旧快照、不猜测修复。
- 新恢复宿主实际成功退出且当前文件再次核验后，才解除屏障并按原设置恢复 Electron LAN。

## 验证入口

- `tests/original-lan-preview.test.mjs` 用真实文件验证持久屏障、维护写入守卫、错误证明、同内容换文件、内容变化和超限文件拒绝。
- Rust `original_lan_release_*` 覆盖未授予、空／意图中断、幂等中止、实际工作线程排空／终态恢复、未知内容和篡改拒绝。
- `tests/electron-original-lan-runtime.mjs` 验证真实 Electron 菜单、同进程 Tauri、实际 Windows 配对／接收确认、上传中交还、原 Electron 接续完整哈希、取消窗口，以及原生／Electron 主进程 SIGKILL 后的持久屏障和显式恢复。Electron 选择和结果通知由测试夹具提供，不能作为生产来源选择 UI 验收。
- `scripts/verify-original-lan-runtime.mjs` 将源码清单、日志、专项证据和产物摘要冻结于独立目录。实际通过范围以该轮 `verification.json` 为准，不能用实现说明代替通过记录。

## 保留门槛

- 本入口仍隔离普通工作区 IPC、编辑器和其他后台业务；LAN 专用交还不能代表整体工作区／浏览器交还。
- 未开放生产来源接管、历史 profile 自动认证、整体持久切换或完整回退；物理双机、真实广播环境、IME／混合 DPI、长期资源、WebView2 缺失和安装包／实际绿色 ZIP 门槛继续按迁移计划执行。
