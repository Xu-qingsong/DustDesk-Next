# 从存活快照准备实际运行 Data

## 当前范围

- 在已固定的正式旧版来源、原 LAN 与原生快照成功决定之上，增加实际运行目录形态的 Data 准备。输出保留原文件字节、相对路径、空目录、精确 Windows 最后写入时间及只读属性；不会复制快照 objects 层、组合清单、浏览器草稿、LAN 状态副本或旧运行锁。
- 复制读取当前护栏持有的快照对象句柄，不先释放再按路径重开。源资产、完整快照、原 LAN、实际 catalog／意图／决定和新输出句柄在同一存活会话中保留。
- 这不是启动新运行时、所有权移交、浏览器草稿导入或生产切换。序列化回执始终为 `productionReady: false`、`migrationComplete: false`；默认 Electron 入口、分支和版本不变，不提交、推送或发布。

## 原生记录与恢复

- 原生记录位于实际来源 catalog 的 `<快照准备 ID>/RuntimePreparation/<运行准备 ID>/`，依次持久写入 `intent.json`、完整 `inventory.json` 和独立 `decision.json`。清单存于输出 Data 外部，不污染运行目录。
- 意图先于输出创建发布；目标只能是固定父目录下的新目录，绝不覆盖已存在目录，不允许位于原安装、Data、userData、浏览器 profile 或组合快照内部。
- 清单包含输出实际物理身份、文件身份／大小／时间／属性／摘要和空目录身份，并与原快照路径、类型、字节数及摘要逐项一致。新回执绑定完整原组合回执摘要、原生准备 ID、输出根身份和清单摘要。
- 发布清单前及成功决定前再次检查原 LAN 和完整活源资产；取消、授权失效、后来新增源文件或输出文件均不能获得成功许可。每个 64 KiB 复制块检查取消及当前授权。
- 中途失败不删除部分输出或猜测完成。重开仅把有意图但无决定的记录持久标为 Aborted；即使所有输出与清单都已写完，也不会升格成功。已有成功决定必须显式查询并核验，不能静默创建第二份输出。
- 成功会话保留实际输出、完整清单和三份原生记录的句柄；重复准备同一目的地及重复核验均复用原句柄并重新哈希。正常关闭、出错或强制退出释放句柄，但保留决定与输出。
- 重开成功准备必须重新取得来源和原 LAN 独占，核验原快照、真实原生决定和输出完整目录。复制目录、替换空目录、同大小且恢复时间的字节篡改、新增文件、硬链接和只读属性变化均拒绝，不改写原成功决定。

## 私有准备通道

- Snapshot 模式增加 `prepareRuntime`、`verifyRuntime`、`queryRuntime`；只读来源租约模式拒绝全部运行准备命令。尚未添加 Electron 公共业务 API、维护菜单入口或实际运行时启动。
- `queryRuntime` 返回范围为 `native-runtime-preparation-metadata-only` 的原生状态，仅用于发现已经持久提交但客户端丢失响应的 ID。它不固定输出，不证明当前输出内容，不授予运行许可；必须另行 `verifyRuntime`。
- 查询采用每页最多 32 条与显式 `nextCursor`，UUID 游标严格校验，原生响应有 64 KiB 上限。4096 条记录的内核分页回归确保不静默截断，完整回执页也在响应边界内。
- 原 LAN 私钥不复制、不导出、不重建；准备目录不包含 LAN identity。传输所引用的外部文件仍是原路径，这一增量不备份或恢复它们。
